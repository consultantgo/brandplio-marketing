Quickstart

Three steps, under five minutes.

01

Mint an API key

Create a key in the Brandplio dashboard. Keys are enterprise-scoped, prefixed bvp_, rotate with one click, and scope per brand.

# app.brandplio.com → API keys → New key
$ export BRANDPLIO_API_KEY="bvp_live_7f2a…"
02

Fetch context

Ask for a persona × product × tone bundle, optionally shaped for a channel. You get a ready-to-use prompt block back.

GET /api/acme/context
     ?persona=ops-director
     &product=platform
     &tone=reassuring
03

Ship it

Drop the prompt block into your system prompt, or connect your MCP client to our hosted server and let agents consume brand natively.

$ claude mcp add --transport http brandplio \
    https://mcp.brandplio.com \
    --header "Authorization: Bearer $KEY"

Model Context Protocol

  • Exposes load_catalog, build_context, and get_combination_prompt as tools.
  • Scopes per API key: same server, different brand, no restart.
  • Hosted over http—connect a URL, nothing to install or run.

Drop-in skill

Brand for content creators, with zero code.

Ship a pre-built skill that content creators paste into Claude, ChatGPT, or Slack. The skill asks the right questions, pulls context through the MCP server or REST API, and returns on-brand output with a short summary of the decisions it made.

  • Conversational resolution. No IDs, no slugs: creators describe intent, the skill translates.
  • Lock a layer. Pin persona, product, tone, or channel for team-specific skills (e.g. “support replies only”).
  • Transparent decisions. Every output ships with a “Context Applied” block, so reviewers see what the skill used.

Authentication

Keys built for how teams actually work.

Keys belong to your account, not a single user. Scope them per brand, rotate them in place, and revoke with immediate effect across every agent that was using them.

  • SHA-256 hashed at rest. We never store plaintext keys: you see a key once, at mint.
  • Brand resolution. Pass X-Brand-Id or ?brand=, otherwise falls back to your default brand.
  • Rate-limited per key. Higher ceilings and burst allowances available on request.
  • Key activity logged. Every key mint, rotate, and revoke is recorded.
